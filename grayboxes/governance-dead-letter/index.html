Scenario

A plan that stopped running

The situationThe Business Department’s Help Assistant (DHA) has been running for a semester. It answers advising questions for business students from the department handbook. The department wrote a governance plan: monthly accuracy reviews, a designated reviewer, and an escalation path. The plan is in the Model Card. Three months in, the reviewer, Dr. Martinez, left the department. No one was reassigned. The monthly reviews stopped. The Model Card still says “monthly reviews by Dr. Martinez.”
MeanwhileThe handbook was updated at midterm with new prerequisites: Intermediate Accounting now requires Principles of Accounting II with a C or better. The DHA’s knowledge base wasn’t updated. Students are getting the old prerequisites, and no one has caught it because no one is reviewing.
The compounding problemThe governance document is now misinformation itself: it describes a process that doesn’t exist. The Model Card has become a false record.
Reviewer left→Reviews stopped→KB went stale→Students got wrong answers→Nobody noticed

The DHA, the handbook, and the people are fictional.

Task 1 · Audit the tags

The three-colour reality check

Each line was tagged when the Model Card was written. Is the tag still true today?

A tag is only as current as the last time someone checked. [T] decays to [U] when the person who tested it leaves, the process changes, or time passes without re-checking.
Why this is a gray box problem

The governance layer became a gray box

What a student sees

An answer with a source citation · a Model Card that says “reviewed monthly”

What a student can’t see

That the reviewer left · that reviews stopped · that the knowledge base is stale · that the Model Card itself is wrong

What the builder can see, if they look

The last review date in the logs (for example, AWS CloudTrail) · the knowledge base upload timestamp · the Model Card version history

Gray box insight: the documentation describes a system that no longer matches reality. Partial visibility plus outdated documentation equals false confidence.

If the builder can see the logs and timestamps, why didn’t anyone catch this? Because nobody was assigned to look.

Key takeaway

Governance is a practice, not a document

A review process that nobody performs isn’t a safeguard. The three-colour rule makes this visible: a [T] that hasn’t been re-checked decays to [U].
